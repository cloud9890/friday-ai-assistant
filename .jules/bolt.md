## 2024-10-19 - Eliminate GC Pauses by Caching Real-time Audio Uint8Array Allocations
**Learning:** The real-time visual canvas renderer in `app.js` runs at ~60 frames per second using `requestAnimationFrame`. On each frame, `drawArcReactor` and `drawSpectrum` were individually invoking `getFrequencyData` from `voice-engine.js`. If audio was unavailable, `getFrequencyData` dynamically synthesized the audio array but used `const synthData = new Uint8Array(count);` to allocate memory on every call (up to 120 times per second), creating a significant garbage collection bottleneck resulting in micro-stutters and high CPU overhead.
**Action:** When working on real-time visualizers or code that repeatedly polls data loops, cache the `Uint8Array` allocations to a class member during instantiation and reuse/overwrite the array via a pointer. Also fetch the data once per loop and pass it down rather than redundantly invoking the getters.
